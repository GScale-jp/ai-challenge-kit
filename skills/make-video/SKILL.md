# /ai-challenge-kit:make-video 台本からデモ動画を作る

提出用の `challenge/demo.webm` を作ります。動画は90秒以内で、Google の AI を使っている画面を入れます。

`<スキルのフォルダ>` は、この `SKILL.md` が置かれているフォルダの絶対パス（パソコン内での完全な場所）のことです。スクリプトは作業フォルダ（`challenge/` があるフォルダ）で実行し、`<スキルのフォルダ>` はスキルを読み込んだときに分かる実際のパスに置き換え、空白があっても動くよう引用符で囲みます。

## 手順

1. `challenge/video_script.md` を読みます。無ければ /ai-challenge-kit:demo-video を案内して止まります。「困りごと」「Google の AI を使っている画面」「誰がどう助かるか・ほかにも広がること」の3区間で、映す画面とナレーションを確認します。
2. 台本の末尾に「自動作成用の場面データ」が無ければ、下の例を台本に合わせて書き足し、本人に見せます。既にあれば中身を確認し、操作や字幕を変える必要があるときだけ直します。字幕は声に出して読める長さにし、Google の AI を使う場面を実際の画面や結果で見せます。
3. アプリの場所を決め、場面データの `appUrl` に書きます。/ai-challenge-kit:deploy で得た URL があれば使えます。このパソコンにあるアプリなら `app/index.html` か `file://` で始まる URL を使います。開発用のサーバー（アプリをブラウザで開けるようにする仕組み）を使っている場合は、起動したまま `http://localhost:8080/` などを指定します。
4. 初回だけ、Playwright（ブラウザの操作と録画をする道具）と Chromium（録画に使うブラウザ）を入れます。ワークスペース直下で、Mac はターミナル、Windows はコマンドプロンプトで次を実行します。入れ終わったらワークスペース直下に戻ります。

   ```sh
   cd <スキルのフォルダ>/scripts && npm install && npx playwright install chromium
   ```

5. ワークスペース直下で次を実行します。先に秒数だけを確認するときはコマンドの末尾に `--check-only` を付けます。以前の `challenge/demo.webm` があれば、中身を確認してから録画します。前の動画を残す場合は `--out challenge/demo-v2.webm` を付けます。

   ```sh
   node <スキルのフォルダ>/scripts/make_video.mjs
   ```

6. `challenge/demo.webm` ができたら、本人にファイルの場所と実際の動画の長さを伝えます。動画を再生して、字幕が読めるか、Google の AI を使う場面が映っているかを確認します。
7. ナレーションは任意です。自分の声を入れるなら、スマホで動画を見ながら声を別に録り、編集アプリで動画に重ねる方法があります。YouTube Studio でも「エディタ」の音声トラックから用意されている音楽を足せます。仕上げた動画も90秒以内に収めます。WebM は YouTube にそのままアップロードできます。ログインし、公開範囲を「限定公開」にして保存する操作は本人が行います。
8. `challenge/progress.md` があれば「動画の作成」を「済」にします。該当の段がまだ無ければ「メモ」に「動画の作成：済」と動画の場所を追記します。ファイルが無ければ作らず、/ai-challenge-kit:challenge を勧めます。
9. 次は /ai-challenge-kit:entry-form と伝えて終わります。

## 場面データの書き方

次の見出しから台本の末尾に書き足します。JSON は、録画する順番や操作を道具に伝える書き方です。

````markdown
## 自動作成用の場面データ

```json
{
  "appUrl": "app/index.html",
  "intro": { "title": "Antigravity で作りました", "caption": "家族の台風への備えをひとつの画面に", "seconds": 8 },
  "scenes": [
    { "id": "problem", "title": "家族の備えが見えません", "caption": "何を買ったか、家族で何度も確認します", "seconds": 12 },
    { "id": "demo", "title": "AI が備えの一覧を作ります", "caption": "家族の人数から、備えるものを表示します", "seconds": 45,
      "steps": [
        { "action": "click", "selector": "#start" },
        { "action": "fill", "selector": "#people", "text": "4" },
        { "action": "press", "key": "Enter" },
        { "action": "wait", "ms": 800 }
      ]
    },
    { "id": "wrapup", "title": "準備の分担が一目で分かります", "caption": "家族のそれぞれが、残っている備えを確認できます", "seconds": 18 }
  ],
  "antigravityClip": null
}
```
````

- `selector` は画面のどのボタンや入力欄を操作するかを示す目印です。例の目印はアプリの実際のものに置き換えます。操作が無い場面は字幕だけを映します。
- 元の台本の「0〜15秒」「15〜70秒」「70〜90秒」を足すと90秒です。最初に導入を入れる分だけ3区間を短くします。例では導入8秒＋12秒＋45秒＋18秒で83秒です。アプリの読み込みや動作を待つ時間も、操作場面の秒数に含めます。合計が90秒ぎりぎりなら、録画の余白を取るため終盤を少し短くします。
- Antigravity で作っている画面を本人が録画した場合は、`antigravityClip` に動画ファイルのパス（ワークスペース直下からの場所、または絶対パス）を書けます。Chromium で再生できる形式の動画を使います。動画は最初に音声なしで再生し、`intro.seconds` で次の場面に進みます。指定が無ければ導入は字幕だけです。導入の秒数の既定は8秒です。
- アプリで本物の AI を使うのにキーの入力が必要なら、本人が手動で操作し、キーが映らない範囲を収録して導入動画に使います。

## 気をつけること

- 録画前に、共有するつもりのない声や顔、個人情報、API キー（AI を使うための合い鍵）が音声や画面に入らないよう確認します。API キーやパスワードは台本やほかのファイルに書きません。
- ログイン、課金、規約への同意、送信の確定が必要な操作は本人が行います。録画用の操作には入れません。
