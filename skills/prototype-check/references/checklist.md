# 作り始める前に聞く4つのこと

先に「何が起きると、この案が成り立たなくなるか」を考えます。使う人に確かめる場合は、一度に1問ずつ聞きます。

1. **今日2時間で動くか。** 使う人が最初から最後まで試せる操作は何ですか。機能を3つに絞ったとき、一番時間がかかる部分はどれですか。例えば別の端末と記録を共有するのが難しければ、1台だけで同じ操作を試します。
2. **90秒以内の動画で見せられるか。** Google の AI に渡すもの、返ってくるもの、使う人が助かる場面を続けて映せますか。何回も入力が必要なら、架空の例を1件だけ用意します。
3. **審査基準にどう答えるか。** 各基準で、強み・弱み・補い方を1行にします。
   - 独創性：今のやり方にない工夫はどこですか。
   - 社会・暮らしへの貢献度：誰の、どの場面の手間や迷いが減りますか。
   - AI 活用の有効性：同じ入力で、AI を使った場合に何が変わりますか。答えが違っていたら誰が確かめますか。
   - 展開可能性：別の人や場所で使うなら、どこを変えれば試せますか。
4. **機密・個人情報を扱わずに試せるか。** 入力、保存、AI に渡す情報、録画に映る情報を順に見ます。実在の店名・人名、他人の連絡先、会社や顧客の資料などがあれば、同じ操作を試せる架空データに置き換えます。

## 作る形の選び方

| 作る形 | 選ぶ目安 | 最初に試すこと |
|---|---|---|
| GAS Web アプリ | Google アカウントで公開できる形で、Google スプレッドシートに記録をまとめたいときです。 | 架空の1件を表に書き込み、画面に表示します。 |
| 静的 Web アプリ | HTML で画面が開き、記録が同じ端末のブラウザにあれば足りるときです。 | 画面を開き直し、1件の記録が残ることを確かめます。AI の操作は別画面で見せる方法もあります。 |
| Cloud Run | 裏側で処理を行うサーバーが必要なときや、外部 API を裏側から呼ぶときです。 | 画面から架空の短い入力を1件送り、結果が1件返るところまで通します。 |
