# /ai-challenge-kit:prototype-check 作り始める前の点検

最初に「このアイデアのどこが危ういか」を探します。例えば、使う人がその場で入力できるか、AI が違う答えを出すと困らないかを具体的な場面で考えます。見つけた弱点ごとに、今日試せる直し方を1つ添えます。

## 手順

1. `challenge/idea.md` を読みます。無ければ `/ai-challenge-kit:idea-spark` を案内して止まります。あれば `challenge/requirements.md` も読みます。要件のファイルがなければ、アイデアをもとに点検します。分からない点があって聞くときは、一度に1問だけにします。
2. [references/checklist.md](references/checklist.md) の問いを使って、次の4点を点検します。
   1. **今日2時間で動くか。** 使う人の操作の流れを1つにし、最小の機能を3つに絞ります。時間がかかる箇所を挙げ、先に試す部分を決めます。
   2. **90秒以内の動画で見せられるか。** Google の AI を実際に使う場面を1つ決めます。何を渡し、どんな答えが出て、その答えで何が変わるかを画面でどう見せるか書きます。
   3. **審査基準にどう答えるか。** 独創性、社会・暮らしへの貢献度、AI 活用の有効性、展開可能性の順に、強み・弱み・補い方を各1行にまとめます。試作の完成度は審査で問われません。
   4. **機密・個人情報を扱わずに試せるか。** 会社や顧客の機密、実在の店名・人名、他人の個人情報が必要になりそうなら、同じ操作を試せる架空データに置き換えます。API キーやパスワードをファイルに書きません。
3. チェックリストの表から、作る形を**1つ**勧めます。選んだ形の名前と、今回それで足りる理由を書きます。

   | 作る形 | 選ぶ目安 |
   |---|---|
   | GAS Web アプリ | GAS（Google Apps Script）で作る形です。Google アカウントで公開でき、データを Google スプレッドシート（表を編集する道具）に置けます。 |
   | 静的 Web アプリ | HTML（画面を作るファイル）だけで開ける形です。記録を同じ端末のブラウザに置けます。 |
   | Cloud Run | サーバー（裏側で処理する場所）が必要な場合や、外部 API（別のサービスの機能を呼び出す窓口）をサーバーから使う場合に選びます。 |

4. `challenge/prototype_check.md` に次の見出しをこの順で使って保存します。前回の点検があれば内容を読んで、今回の結果に更新します。

   - `# 試作の点検`
   - `## 結論`（「このまま進む」か「ここを直して進む」のどちらか）
   - `## 作る形`（1行目に「GAS Web アプリ」「静的 Web アプリ」「Cloud Run」のどれか1つを書き、次の行に理由を書きます）
   - `## 今日2時間で動くか`（機能3つと、先に試す部分）
   - `## 動画で見せる場面`（入力、Google の AI の出力、使う人に起きる変化）
   - `## 審査基準`（4基準を各1行）
   - `## 危ういところと直し方`（弱点ごとに直し方を1つ）
   - `## 機密・個人情報`（使う架空データ、または入力しない情報）

   今日試せる直し方がなく作り始められない場合は、結論に「ここを直して進む」と書き、次の行に何を直すまで作り始められないかを明記します。作る形は現時点の候補として記録し、手順6で `/ai-challenge-kit:idea-spark` に戻ります。
5. `challenge/progress.md` があれば、「試作の点検」を「済」にします。その行がない形式では `## メモ` に「試作の点検：済（challenge/prototype_check.md）」を記録します。同じ記録があれば更新し、案を見直す場合はそのことも添えます。ファイルが無ければ作らず、`/ai-challenge-kit:challenge` を勧めます。
6. 試作に進めるなら、次は `/ai-challenge-kit:kabeuchi` で要件を詰めるよう勧めます。案から見直す必要があれば、`/ai-challenge-kit:idea-spark` に戻ります。

## 「おまかせ」と言われたとき

保存済みの案を点検します。例えば「台風の前の家族の備え分担」では、家族間の共有が2時間に収まらないおそれがあります。静的 Web アプリ1画面に絞り、① Gemini で作った架空のリストを取り込む、② 担当を付ける、③ 完了に印を付けて同じ端末に保存する、とした点検案を見せます。動画では Gemini でリストの案を出す場面を映します。「この点検案で進めてよいですか」と一問だけ聞いてから保存します。`challenge/idea.md` が無ければ手順1に従います。
