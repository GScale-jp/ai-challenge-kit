# /ai-challenge-kit:idea-spark 応募のアイデア出し

身近な困りごとや好きなことをもとに、コザの題材も参考にしながら、Google AI Challenge に出す案を1つ選びます。完成度は審査で問われないので、変化が伝わる小さな案から考えます。

## 手順

1. 次の3問を**一度に1問だけ**聞き、答えを待ってから次に進みます。実在の店名・個人名や他人の個人情報が出たら、「商店街の店」「家族A」などに伏せて話すよう促します。会社や顧客の機密も使いません。
   1. (1/3) 最近、暮らし・仕事・勉強などで、何を面倒だと感じましたか。
   2. (2/3) その困りごとは、どんな場面で起きましたか。（いつ、どこで、何をしていたか）
   3. (3/3) あなたが好きで、アイデアの題材にしてみたいことは何ですか。
2. [references/scenarios.md](references/scenarios.md) を読み、答えに近いシナリオ3つと、本人の答えを混ぜた新案2つを、同じ形の「アイデアカード」で見せます。元のシナリオに近い案も、本人の言葉に合わせて書いてかまいません。

   ```markdown
   ### 題
   - 誰が:
   - 場面:
   - AI で変わること:
   - 部門:
   - 最小の形:
   ```

3. 「どの案を試したいですか」と聞き、本人が選んでから `challenge/idea.md` に保存します。`challenge/` は必要なら作ります。前の案がある場合は内容を読み、差し替えてよいか本人に確認します。次の見出しをそのまま使います。

   - `# 応募のアイデア`
   - `## 題`
   - `## 誰が`
   - `## 場面`
   - `## 困りごと`
   - `## AI で変わること`
   - `## 部門`
   - `## 最小の形`

4. `challenge/progress.md` があれば「アイデア出し」を「済」にします。その行がない形式では `## メモ` に「アイデア出し：済（challenge/idea.md）」を記録します。同じ記録があれば更新します。ファイルが無ければ作らず、`/ai-challenge-kit:challenge` を勧めます。
5. 次は `/ai-challenge-kit:prototype-check` で、作り始める前に案を点検するよう勧めます。

## 「おまかせ」と言われたとき

3問の代わりに、次のカードを見せます。「この例題で進めてよいですか」と一問だけ聞きます。同意が取れたら例題を選んだ案として扱い、手順3の見出しで保存してから手順4・5に進みます。前の案を差し替える場合は、例題を見せるときに差し替えることも伝えます。

- 題：台風の前の家族の備え分担
- 誰が：誰が何を準備したか分からずに困る家族
- 場面：台風が近づく前に、飲み水や懐中電灯の準備を分けるとき
- 困りごと：口頭で分担すると、誰が何を済ませたか分からなくなります
- AI で変わること：Gemini が架空の家族の条件から確認リストの案を作り、家族が分担を決めやすくなります
- 部門：暮らしと家族
- 最小の形：静的 Web アプリ。ブラウザでリストを開き、担当と完了を端末内に保存します
